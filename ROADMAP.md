# Roadmap

navstack is a mobile-robot navigation and control platform. This document tracks
what is implemented and the planned direction.

## Architecture

```
Scenario / Map ──► Global Planner ──► Path ──► Local Planner / Controller ──► Drive-type command
   (env + MJCF)     (A*/Hybrid A*/RRT*)        (DWA / MPC / Pure Pursuit / RVO)        │
        ▲                                                                              ▼
        └───────────── Perception (lidar / vision) ◄──── MuJoCo Sim (6 drives, dynamic obstacles)
                                     │
                                     ▼
                       Benchmark harness ──► metrics ──► dashboard / plots / CSVs
```

## Implemented

- **Planners:** A*, Dijkstra, RRT, RRT*, PRM, PSO, APF, semantic / terrain-aware A*,
  and a kinodynamic Hybrid A* (`Trail/`).
- **Simulation:** MuJoCo physics simulator with a procedural MJCF generator for six
  drive types (differential 2WD/4WD, mecanum, omni-3, Ackermann, bicycle) and
  closed-loop physics path following.
- **Controllers:** Pure Pursuit, Stanley, Proportional, DWA, and an LTV-MPC
  path-follower, with a genetic-algorithm auto-tuner.
- **Dynamic obstacle avoidance:** Velocity Obstacles / RVO, including reciprocal
  multi-robot swarm coordination.
- **Balancing & RL:** self-balancing Segway with LQR / pole-placement / SMC / MPC /
  RL (PPO) control, linearized dynamics, region-of-attraction analysis, and a
  Gymnasium training environment.
- **Perception:** LiDAR raycasting and color-blob vision.
- **Tooling:** reproducible benchmark harness with statistics, analytics dashboard,
  Streamlit explorer, PySide6 control center, unified CLI, test suite, CI, and a
  documentation site.

## Planned

- **Local planning:** Timed Elastic Band (TEB) and MPPI (sampling-based MPC).
- **Learning:** an RL local planner for the mobile base, benchmarked against DWA/MPC.
- **Multi-robot:** priority-based and conflict-based search (CBS) planning, plus
  formation control.
- **Perception-driven navigation:** costmaps built from live sensor data and SLAM.
- **Benchmarking:** larger scenario suites (maze, narrow corridor, dynamic crowds)
  with tracking-RMSE and control-effort metrics.

## Benchmark strategy

- **Scenarios:** seeded random maps across difficulty classes (sparse, cluttered,
  maze, narrow corridor, dynamic obstacles).
- **Metrics:** success rate, path length, smoothness, minimum clearance, planning
  time, tracking error, and control effort.
- **Output:** a leaderboard and plots regenerated by a single command so the
  reported numbers always reflect the current code.
